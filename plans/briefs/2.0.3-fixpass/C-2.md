## The items, with the pinning test each one needs

C4  `_maybe_escalate` (agent/loop.py) honours offline mode: with offline on,
    an escalation whose `to` is a cloud route does not fire (log one line at
    DEBUG, show the escalation card's "held: offline" state once). Test:
    offline + trigger -> model unchanged.
C5  The auto-switch must never leave a session silently on the cloud model:
    the switch is announced in the transcript (the escalation card the notes
    describe), the status bar shows the switched model, and `/escalation`
    reports it; print mode writes the switch to the result's metadata. Test:
    after a trigger, the transcript/events contain the card and the status
    event carries the new model.
C6  `tool_failures` counts only real tool errors, never permission denials
    (interactive "No", deny rules, PreToolUse hook blocks, abort). Test: three
    denials -> no escalation; three real errors -> escalation.
C7  Per-role escalation override takes effect (`roles.py`,
    `agent/escalation.py`): `{"model": ..., "escalation": false}` on a role
    turns it off for that role; normalisation keeps the key. Test: a role with
    escalation false never escalates; one without the key inherits the global.
C8  `add_savings` is gated on the CURRENT model being local (resolve at the
    time of the turn), not on a price pinned at session start; after a switch
    to a cloud model savings stop accruing, after a switch back they resume.
    Test: switch sequence local -> cloud -> local; saved_usd grows only on the
    local turns.
C9  The TUI shows "saved $x": forward `saved_usd` from `message_end` in
    `tui/dispatch.py` and include it on the status event where the finding
    says. Test: a message_end with saved_usd updates `StatusBar.saved_usd`
    (use the Static.update capture technique from
    tests/test_status_event_mcp_count.py).
C10 `events.status()` includes the three `ollama_*` keys ONLY when the
    producer passes them (presence means "a reading"), the same rule the MCP
    count now follows in that function (see commit ec9a282 and
    tests/test_status_event_mcp_count.py for the pattern); `apply_status`
    keeps the last reading when the key is absent and clears on an explicit
    None only where the finding says it should. Test: a status event without
    the keys leaves the throughput chip unchanged.
C11 `Controller.list_models()` lists `ol:` (every configured host), `hf:local/*`
    (every registered local server and the model dirs) and `hf:mlx/*` groups
    with the same columns as the other groups, so the picker and `/model`
    completion see them. Test: a config with one Ollama host and one local
    server yields both groups.
C12 `u` works from the picker's default state: focus starts on the list (or
    the key is bound at the screen level so it works while the filter has
    focus; typing still filters when the user types a letter other than the
    bound shortcuts only if the finding says so; otherwise keep the filter
    focused and bind `u` at the screen level with a visible footer hint).
    Test: a TUI test presses `u` on the fresh picker and the action fires.
C13 The VRAM-aware redirect applies to real spawns too: `config/agents_md.py`
    child builds use `resolve_role_ref` (or the shared rule) so a sub-agent on
    a local model that does not fit is redirected the same way `/roles`
    shows. Test: a child spec on an oversized local model resolves to the
    redirect target.
C14 TUI `/local add <path>` and `/local forget <path>` reach `add_model_dir`/
    `forget_model_dir` exactly like the print-mode builtins (one shared
    implementation). Test: the TUI dispatcher with `/local add <scratch dir>`
    registers the dir; `forget` removes it.
C15 Saving the wizard's Ollama tab with every field blank registers the local
    daemon as the help text promises without overwriting an existing
    `ollama.hosts` list: blank fields mean "add or keep the default loopback
    entry", never "replace the list with a blank-named host". Test: an
    existing LAN host entry survives a blank-tab save; a fresh config gets the
    loopback default.

EXTRA (owner report, status bar MCP count): `Session.status_event` in
