## What already exists (verify, then build on it)

- `Session.turn(text, images=None)` in `halo_harness/agent/loop.py` already
  accepts a list of Anthropic-shaped image blocks
  (`{"type": "image", "source": {"type": "base64", "media_type": "image/png",
  "data": "<base64>"}}`); the loop already captions them in the transcript
  (`_image_caption`) and there is per-dialect handling to find and extend
  (grep `image` / `media_type` in loop.py, providers/request.py,
  providers/responses_request.py, providers/ollama_request.py,
  agent/codex_turn.py, agent/cc_runtime.py).
- `halo_harness/tui/images.py` renders inline images where the terminal can.
- `halo_harness/tui/widgets/input.py::PromptInput._on_paste` handles TEXT
  pastes (`pasted[n]` placeholders); `tui/app.py::_submit_prompt` turns the
  input into `Controller.submit(...)` -> `Command("user_input")` ->
  `Session.turn`. Nothing reads an IMAGE off the OS clipboard today.
- `tui/clipboard.py` holds the OSC-52 copy path (write side); the read side
  is new.

## Deliverables

1. `halo_harness/tui/clipboard_image.py` (new): `read_clipboard_image(
   backend=None, timeout_s=2.0) -> ClipboardImage | None` with
   `ClipboardImage(path: Path, width: int | None, height: int | None,
   media_type: str, bytes: int)`. Readers tried in order, each a subprocess
   under the timeout, no new hard dependency:
   - Windows: `powershell -NoProfile -Command` with
     `Add-Type -AssemblyName System.Windows.Forms; $i =
     [Windows.Forms.Clipboard]::GetImage(); if ($i) { $i.Save('<tmp>.png',
     [System.Drawing.Imaging.ImageFormat]::Png); 'ok' }` (fallback
     `Get-Clipboard -Format Image`); the PNG goes straight to the target path.
   - WSL: the same through `powershell.exe` when `/proc/version` mentions
     Microsoft, converting the Windows temp path with `wslpath`.
   - macOS: `osascript -e 'the clipboard as «class PNGf»'` written to the
     path (fallback: `pngpaste <path>` when installed).
   - Linux: `wl-paste --type image/png` then `xclip -selection clipboard -t
     image/png -o`, stdout to the path; `xsel` as a last try.
   - Any platform: Pillow's `ImageGrab.grabclipboard()` ONLY when Pillow is
     importable (optional import, never required).
   `backend` is the test seam: a callable returning the PNG bytes (or None)
   so tests never touch a real clipboard. The reader never runs on the UI
   thread (the TUI calls it from a thread worker).
2. Storage and limits: `~/.halo/attachments/<session-id>/clip-<n>.png`
   (state dir via config.paths, so BRIDGE_TEST_HOME scopes it); PNG or JPEG;
   if Pillow is importable, downscale images whose long side exceeds 1568 px
   (keep aspect, re-encode PNG); without Pillow keep the file as is; refuse
   anything over 5 MB after that with one plain line. The transcript log
   stores the PATH (an `image_path` field on the user node), never the base64,
   and resume re-reads the file to rebuild the block (missing file -> the
   caption says so, the turn still runs).
3. TUI: Ctrl+V and Shift+Insert whose paste event carries no text, plus an
   explicit `/paste` command (and `/paste <path>` for a file), read the
   clipboard image in a worker and add an attachment chip to the prompt area:
   `[Image #1 1024x768]` (or `[Image #1]` when the size is unknown). A pasted
   text that is the path of an existing .png/.jpg/.jpeg/.gif/.webp file (a
   drag from Explorer/Finder, with or without quotes) attaches that file
   instead of inserting the path. Backspace with the cursor at the start of
   an empty-after-chip input, or `/images clear`, removes the last chip;
   `/images` lists pending attachments. On submit the chips become image
   blocks passed with the prompt all the way to `Session.turn(text,
   images=[...])`; the transcript shows the image inline via tui/images.py
   when supported, else the caption line. Over SSH there is no remote
   clipboard: when every reader returns nothing, show one line "no image on
   this machine's clipboard; use /paste <path> or drag a file".
4. Dialect conversion for the image blocks, one function per shape in the
   provider layer, used by the request builders: Anthropic-shaped rungs keep
   the block; OpenAI-shaped chat completions and Responses get
   `{"type": "image_url", "image_url": {"url": "data:<media>;base64,<data>"}}`
   (Responses: `input_image`); `ol:` puts the base64 in the user message's
   `images` list; `cx:` passes the saved path with `codex exec -i <path>`
   (verify the flag with `codex exec --help`, under a 20 s timeout, never
   `codex login`); `cc:` includes the saved path in the prompt as a file
   mention. A model whose catalog row says no vision gets one plain line
   "<model> does not take images; attached as a path" and the turn proceeds
   with the path mention instead of a provider 400 (use the catalog's
   modalities/vision field where present; unknown -> send the image).
5. Print mode: `--image <path>` (repeatable) on `halo -p`, and stream-json
   `user_input` accepts content blocks with `image` entries (file path or
   base64), Claude Code parity.
6. Docs: docs/COMMANDS.md (`--image`, `/paste`, `/images`), docs/TUI section
   that documents keys (find it; docs/SLASH-COMMANDS.md holds slash docs),
   docs/CONFIG.md if a setting is added (none is required), CHANGELOG
   `## [2.0.3.1] - unreleased` section above [2.0.3] with the feature
   bullets. Bump `halo_harness/__init__.py` `__version__` to "2.0.3.1".
