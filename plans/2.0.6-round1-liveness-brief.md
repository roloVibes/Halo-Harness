# 2.0.6 round 1: TUI liveness -- never look frozen again

Owner (rolo), 2026-10-07 ~05:20, mid-release: "the seconds keep ticking
and I see a steering message, tells me nothing what is going on; waiting
too long for a response, need better clarity it's not frozen." The 2.0.5
release run made it concrete: a long turn with no token output is
indistinguishable from a dead one unless you already know what to look
for. Roadmap: 2.0.6 hardening gains this as the ADDED liveness block.

## What exists (survey, transcript.py + app.py)

- `PhaseLine.tick()` runs on EVERY drain tick (~30x/s) for every live
  phase line; the rendered text changes only when a whole second rolls
  over (`format_elapsed_seconds` is integer seconds).
- States: Thinking / Writing / Waiting for model, with `(Ns, no tokens
  yet)` and a done-summary ("Thought for Ns · M tokens").
- `last_activity_at` is tracked but only used for the no-data suffix.
- The running tool card shows the tool name; the status bar shows a
  background-jobs count.

## Deliverables

1. **Sub-second elapsed on live lines.** Live phase lines (and running
   tool cards) render `12.4s` -- tenths, from the existing tick; the
   integer-second form stays for the final "Thought for Ns" summary.
   A stalled RENDER is now visibly different from a stalled turn: a
   frozen tenth means the UI died, a running tenth with a static
   "quiet Ns" means the upstream did.
2. **Name what is being waited on.** The phase line carries the wait
   target: `model` (streaming), `tool: Bash` (a tool round, name from
   the running card), `agent: implementer` (a subagent round),
   `suite`/`bg` when a background job gates the turn. Wire from the
   existing events (tool card begin/end, Agent spawn/handback, bg job
   state changes) -- no new core events, TUI-side only.
3. **Last-activity age.** Once a phase has seen ANY activity, append
   `· quiet 4s` (seconds since `last_activity_at`), refreshed on the
   same tick. Under 2s: omitted (normal think-time between chunks).
   This makes a mid-stream stall pop without any threshold config.
4. **Background jobs in the status bar.** The count chip becomes
   `⚙ 2 bg` -> `⚙ 2 bg (suites 1, agents 1)` style: job kinds, one
   word each, from the JobRegistry's own labels; a finished-since-
   last-look job flashes its one-line result.
5. **The hang-watchdog's heartbeat, visible.** The existing hang
   detector dumps a log; while it is counting (heartbeat stalls at Ns),
   the status bar shows `⏠ hang-watch Ns` so the owner sees the SAME
   clock the watchdog will act on. No behavior change -- display only.

## Non-goals

- No new settings, no thresholds, no config keys -- everything derives
  from clocks and events that already exist.
- No core (agent loop) changes -- TUI + dispatch only.
- Not: retrying/killing on stall (that is the watchdog's own round).

## Tests

- PhaseLine unit: tenths render on tick; quiet-Ns appears after 2s of
  no append; wait-target naming per state; summary keeps integer form.
- Pilot: a scripted slow stream shows `quiet Ns` growing; a tool round
  renames the wait target; done lines are unchanged (snapshot suite).
- Status bar: bg kinds render from a fixture registry; hang-watch chip
  appears when the detector is counting.
- Snapshots: the affected tui-snapshots regenerate (UPDATE_SNAPSHOTS=1
  flow), no other SVG changes.

## Verification

Full three-platform suite + CI green, one live TUI check against a real
slow model (ol:qwen3-coder:30b@lan with a long prompt) watching the
tenths tick and quiet-Ns grow, then commit round 1.
