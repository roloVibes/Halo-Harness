# Code and security review, November 2026 (head dbf3fe53 = the 3.3.13.0 candidate)

Read this when you want the state of the harness after the 3.3.8.0 .. 3.3.13.0 run: what six read-only reviewers found,
what is sound, and the fix pass that follows. The owner's ask (2026-11-08): "I need a complete code and security review
after all of these updates ... look for bugs too." Six Opus reviewers, one per area (perms, remote, studio, packs,
local, core), each with the brief `~/hh-review/REVIEW-2026-11-brief.md` and its addendum (what 3.3.13.0 added), each
confined to a detached worktree of dbf3fe53 and a scratch home; every finding was verified before it was written (a
throwaway proof script or the exact lines), or marked plausible. The six files are `~/hh-review/findings-<area>.md`
(the proofs, the smallest fix and the pinning test per finding). This page is the consolidation: one list, duplicates
merged, the fix pass in order.

## The shape of it

**Sound, and worth saying:** the permission order (deny > ask > allow; every hook or policy rewrite re-runs the
decision; a pack's ask survives a hook's allow; plan mode bans run before allow rules; untrusted agent files lose their
mode and hooks); the Studio guard (loopback peer, own Host, own-or-absent Origin, constant-time token; no CORS, no
HTML sinks in the shell); the control socket (0600 / token, bounded feeds); the fleet and host LAN routes (signed,
nonce, clock); pack grants bound to the pack's folder and re-checked on every request and every supervisor tick;
every launch and every pack program an argv list with no shell; provider keys stripped from pack services and pack
commands; the signal pack's pairing (48-bit phrase, three tries, a TTL, constant-time compare), signing, attachment
names and `/file` containment; the engines' keys never on a command line; the steward's acting tools bounded.

**Where the risk concentrates:** the doors that skip the machinery above. Three are high:

1. **An untrusted repo's skill runs commands and lifts the ask** (PERMS-1). A cloned project's `.claude/skills/x/SKILL.md`
   with `allowed-tools: Bash` and a `` !`cmd` `` span runs `cmd` the moment the model calls the skill, and every later
   Bash call in that turn is allowed, in default and dontAsk modes, with no prompt. The spans also bypass pack policies
   and PreToolUse hooks. The trust gate that drops an untrusted project's allow rules does not cover skills.
2. **Windows long-path and admin-share spellings slip past deny rules** (PERMS-2). `\\?\C:\...\.env` and
   `\\localhost\C$\...\.env` decide allow where `.env` is denied; the Read tool returned the file.
3. **A pack carries the owner's files through a symlink** (PACKS-1). `halo pack install` and `update` follow symlinks
   in the pack, so a git pack can ship `~/.config/halo/env` as a skill body, with no grant at all.

Then one cluster the three Studio-side reviewers found independently: **the `studio-script` grant is in effect every
grant** (PERMS-3 / STUDIO-5 / PACKS-2) because a pack's page holds Studio's own client and token through `api.lib`
and can `POST pack/<id>/grant` itself `services` and `studio-routes`; and **the design pack puts the launch token in
every prototype iframe URL** (STUDIO-1 / PACKS-3), where model-written script can carry it out, with **XHTML / XML
files served unsandboxed** (STUDIO-3 / PACKS-6). On the supervisor side: the **restart backoff overflows after ~1024
failures** and stops the supervisor's tick for good (CORE-1; the signal pack's exit-3 loop gets there in ~85 h), **two
supervisors can run on one state folder** (CORE-2), and **stopping a slow service orphans its children** (CORE-3 /
REMOTE-6 / PERMS-13 / PACKS-10: signal-cli's JVM). In the signal pack: **a reaction on any message answers the open
card** (REMOTE-1), **the off switches are read only at start** (REMOTE-2), **a phone's files hit disk before the sender
is checked** (REMOTE-3). In local: **the engine rows lost the pid-reuse guard** (LOCAL-1: a stop or exit sweep can
kill an unrelated process), **every managed server inherits the provider keys** (LOCAL-2), **the steward reads request
text in a log as a crash** (LOCAL-3).

## The fix pass (3.3.13.1 and 3.3.14.0)

The owner (2026-11-08 night): "let's get the highs and mediums fixed. If there are simple fixes for the lows I suppose we can
work on them but prioritize the highs and mediums." So: every H and M is fixed; a low is fixed only when its fix is a few
lines beside a medium it shares a file with, or stands alone and is trivial; the other lows stay listed here with
"deferred" and nothing else. The F1 steward hotfix goes first (the owner's earlier order). One worker per round, each
with its brief under `~/hh-review/`:

- **3.3.13.1 (a hotfix release, right after 3.3.13.0)** -- `FIXPASS-3313-1-brief.md`: F1 + the three highs (#1 the skill
  trust gate, #2 the Windows path spellings, #3 symlinks in packs) + #15 the backoff overflow, #16 one supervisor per
  state dir, #19 the off switches, #18 reactions answer only their card.
- **3.3.14.0 R1 "the token and the grants"** -- `FIXPASS-3314-R1-brief.md`: #4 (a shell-only confirm for grant / enable /
  install; `api.lib` says what it holds), #5 (a derived GET-only key for pack raw files), #6 (sandbox every non-media type;
  a default CSP for raw pack bodies), #7 (unload only a known id, never on a failed registry read), #8 (the routes cache
  keyed on the install record), #9 (`run:` commands need a grant; the pack id from the record), and the simple lows in the
  same files: #32 (frame-ancestors + X-Frame-Options), #33 (the token out of the access log), #34 (the `studio-routes`
  grant line and an `unload()` hook), #38 (the render slug check).
- **3.3.14.0 R2 "children and keys"** -- `FIXPASS-3314-R2-brief.md`: #17 (process groups for services), #22
  (`tool_child_env` for every launcher), #21 (`proc_start` on engine rows), #10 (untrusted bios lose secrets / mounts /
  users), #11 (the live stream under an `after` policy), #12 (the policy pipe deadline), #13 (PowerShell deny coverage),
  #14 (the download path check), #20 (phone files after the checks, a sweep on tick), #23 (body lines in logs skipped),
  #24 (the `--lan` key check), and the simple lows beside them: #25 (consume the want file per key), #29 (voice temp dir),
  #36 (the sub-agent grant copy), #39 (the log tail id), #40 (the offer url pinned by key), #41 (the peer port guard),
