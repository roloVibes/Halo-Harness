# Halo Studio

Read this when you use Halo Studio, the browser console where you watch every agent work: the Session dashboard, your agents, workflows and maps and their runs in Agents, and designs.

`halo studio` opens Studio in your browser: where you see every agent of a session live (what it thinks, says, runs and costs), shape the work (agents, workflows and the map, goal runs) and steer it. Its editors write the same files the CLI edits: an agent is `~/.halo/crew/agents/<name>.yaml`, a workflow `~/.halo/crew/workflows/<name>.yaml`, a map `~/.halo/crew/maps/<name>.yaml` (or `.halo/crew/` in a project), and Studio reads and writes them through the exact functions `halo agents`, `halo workflows` and `halo maps` use. Nothing is a second source of truth.

**What Studio shows is what is on disk, as it changes (3.2.2.0):** a map your session edits, `halo maps use`, an agent saved from the terminal appear within two seconds, no refresh (the server watches the crew folders, the config and layout files and sends `files_changed`). A form you are editing keeps your draft and offers **Reload** or **Keep mine**; a file deleted on disk leaves the list. How: [The live feed](STUDIO-feed.md#the-live-feed).

```sh
halo studio                 # starts a local server, opens the browser in the mode you used last
halo studio --mode agents   # Agents (3.6.0.2: four tabs; on Live while a session you talked to is open); roles, orchestra and team land on the Map
halo studio --session       # 3.1.4.0: the Session dashboard on this harness's newest live session (or --session <id>)
halo studio --mode setup    # 3.3.0.0: Setup, the wizard's blocks as forms; the door: `halo init` opens it (STUDIO-setup.md)
halo studio --no-open       # prints the URL only (SSH, a headless box)
halo studio --port 8765     # a fixed port instead of a free one
halo studio --stop          # stop the Studio running for this home, whichever launch started it
```

**Session** (`halo studio --session`) is where you watch and steer your own session: the Live column is the main thing (3.6.0.0 R0a: the stage), every agent's line in the live log's columns (the time, the kind, who) under a timeline lane per live agent, with an agent and a kind pick, and the Steer box always at its foot, addressed to the agent you pinned or else the session's main agent, Pause and Stop beside it (3.1.7.0); its agent tree, its cost and the rest are buttons in the view bar above it, each opening a drawer beside Live. How it works: [Session](STUDIO-sections.md#session). Since 3.3.0.0 the box names its target and the call it reaches, and **Export** saves the session as one Markdown file, the session export: [Studio: steering and exporting a session](STUDIO-session.md). Its spend, tokens, turns and context
move on the session's own `message_end` and `status` frames, the moment the
terminal's status bar moves (3.1.8.0); the frames the tab reads and the
delays that remain, each with its number, are in
[The live feed](STUDIO-feed.md#the-live-feed). **Studio without a terminal (3.3.11.0 R2):** Session's **New session** (the Start view, or the Prompt panel with no session here) starts a whole session from Studio -- pick the model and the folder; Studio's server runs `halo --headless` as a detached child, the terminal's own loop and session log with its control socket as the only door, so you type into it and answer its asks in the Prompt panel, closing the tab never ends it and **End session** does ([A session without a terminal](STUDIO-session.md#a-session-without-a-terminal-33110-r2)). And **Agents -> Live** (`L` in Agents) draws the session's real agent tree on the whole page, every agent Auto spawns 1:1 with the terminal's `/agents live`, the Session Map its thumbnail ([Agents](STUDIO-sections.md#agents)); a goal run is a job there, its lanes under its lead, its report on its own page, Goal run ([STUDIO-orchestra.md](STUDIO-orchestra.md)).

One Studio per machine (3.0.2.0): while it serves, `~/.halo/studio.json` holds its pid, port and token (private), and a second `halo studio` reuses that instance (prints its URL, opens the browser) instead of starting another. 3.6.0.0 R10: a Studio belongs to the launch that started it (`halo init`, `halo`, `/studio`, `halo studio`) and closes with it; a shell command that starts one (`halo setup ...`, `halo studio --edit ...`, `halo init --no-launch`) holds its terminal while it serves, and a Studio of this home that another live launch owns is used as it is ([PROCESSES.md](PROCESSES.md#studio-belongs-to-the-launch-that-started-it)). `halo studio --stop` ends the one running, whoever started it; a page whose Studio has gone says "Studio has stopped" ([TROUBLESHOOTING.md](TROUBLESHOOTING.md#studio-has-stopped)). `halo_harness/studio/launch.py` is the small module behind both.
Since 3.2.2.0 Studio ends with the halo session that quits: a quit
(`/quit`, Ctrl+C twice, Ctrl+D, Ctrl+Q) stops the Studio in `studio.json`
too (its shutdown route, then the signal) and says so in its last line
(`stopped: Studio (pid 4242)`), unless another halo session of this home is
still open (the last one to quit ends it). `halo update` stops it before
installing; `halo studio` afterwards starts the new version.

Inside the TUI, `/roles` opens Studio straight into Agents on the Map from the live session (3.3.16.0; the Map since 3.6.0.0); bare `/studio` (3.1.4.0) opens the **Session** section (`Alt+1`) on the session you are in, `/studio [session|agents|local|packs|setup|settings]` opens that section (`roles`, `orchestra` and `team` land on Agents' Map) (3.3.13.0 R2: or a running pack's own, `/studio <pack>--<section>`; the design pack's `/design`), and `/studio url` prints the URL without opening a browser.
The sections' keys are `Alt+1`..`Alt+6`: Session, Agents, Local, Packs, Setup, Settings ([STUDIO-agents.md](STUDIO-agents.md): Team, Roles and Orchestra in one since 3.3.16.0; [STUDIO-local.md](STUDIO-local.md): the machines that serve your local models, `halo local`); the pack's own sections take `Alt+7` to `Alt+0` (3.3.13.0 R2: Design is the design pack's section, [its README](../halo_harness/templates/packs/design/README.md)). **Quiet by default (3.3.2.0):** nothing opens on its own when you open a section (the **?** in the header and each panel's help are one click away), the sections are a 56 px icon rail (its chevron expands it; it holds the sections only), a view's panels are buttons in its **view bar** and its layout the header's **...**, the inspector stays closed until something opens it, `F` is **Focus**, each view opens on its main thing with most of the room (3.6.0.0 R0a, the stage: every other panel a drawer beside it or a tab in its place, never a tile; nothing under 12 px, no panel that scrolls sideways; one spacing and type scale, no density setting: [the shell](STUDIO-shell.md#the-shell-3030)). A model running in a
Halo session knows this too: the system prompt names Studio, its modes
and the command, so "open the GUI for roles" runs `halo studio --mode agents`.

**Settings (3.3.3.0, `Alt+6`)** is every key of `~/.halo/config.json` in one place: a page per group
(General ... Local), each key a row with its help line, its value against its default, Reset to default
and the exact `halo config set` line, a change saved at once with when it takes effect, a search across
every group and a palette entry per row. The rows come from one catalog (`halo_harness/settings_catalog.py`)
that a test holds to the config schema and to [CONFIG.md](CONFIG.md)'s key table; `halo settings [group]`
opens it ([the section](STUDIO-sections.md#settings)).

## Look

Studio is a holo ops console (a near-black navy, glass panels, cyan for what is live, amber for what needs you, mono for data), and **the ornament goes on the thing you look at (3.3.2.0)**: every panel is one title line (its title, its **?**, a close, a **...** menu) and a plain 1 px border; only the focused panel (the one you clicked, else the section's main panel) carries the HUD corner brackets, the glow and the mono data line. A panel's one-line "what it is" is the first line of its **?**, and an empty area does not say it is empty twice. There is one spacing and type scale (3.6.0.1 removed the comfortable / compact density button, which changed only a few pixels).

This page is the entry point; the content lives in the parts below, one per task.
